# Загрузки через свой файловый менеджер — разбор и карта

## Цель
**Один файловый менеджер на весь проект:** при любой загрузке/выборе файла выскакивает он, а с компа грузим только внутри него (в дерево через кнопку «Загрузить» в модалке).

- Везде: выбор файла = только через наш FM (admin-new-extra-3.js).
- Загрузка с диска в проект — только внутри FM (кнопка «Загрузить» в модалке → `/api/files/upload`).

---

## Где «споткнулись»

### 1. Бандл нельзя было патчить
- **admin-new.html** подключает один большой **admin-new-bundle.js** (материалы, кромки, каталог, меню и т.д.).
- Логика выбора файла в бандле: по клику вызывается `input.click()` → открывается **системный** диалог.
- Попытка заменить в бандле `input.click()` на `openFileManager()` через скрипт **patch-bundle-fm.js** привела к:
  - **Vite:** парсер падал на длинных строках с HTML (`<img ...>`) — «invalid JS syntax».
  - **Синтаксис:** при заменах regex терялись/ломались скобки, появлялись ошибки в других местах (строка 11291 и т.д.).
- **Откат** (revert-patch-bundle-fm.js) тоже ломал скобки и строки.
- Итог: бандл **не трогаем**. Используется бандл из резервной копии, без правок.

### 2. Решение без правки бандла — делегирование
- В **admin-new-extra-3.js** (подключается после бандла) висит **один** обработчик на `document` (фаза capture).
- Он срабатывает по клику на `.fa-folder-open` внутри известных блоков (превью текстур, иконка кромки и т.д.), делает `preventDefault` + `stopPropagation` и вызывает `openFileManager(...)`.
- Так наш FM открывается **без изменения** admin-new-bundle.js.

### 3. Корень проблемы на вкладке «Материал»
- В форме редактирования материала (**material-item-edit**) бандл вешает клик не только на иконку папки в превью, но и на кнопки **«Выбрать изображение»** (`#material-texture-upload-btn` и т.д.). По клику по кнопке вызывался `input.click()` → системный диалог.
- **Решение:** перехватывать и кнопки, и любой клик внутри блока превью (не только по `.fa-folder-open`). Список кнопок и превью задаётся в `admin-new-extra-3.js` (fmButtonIds, fmPreviewIds).

## Карта: где выбор файла и кто им управляет

### Уже через openFileManager (отдельные скрипты, не бандл)
| Место | Файл | Примечание |
|-------|------|------------|
| Панель (иконки, текстуры) | admin-panel.js | openFileManager уже вызывается |
| Шаги комнаты, текстуры и т.д. | admin-room-settings.js | openFileManager уже вызывается |
| 3D модели (модель, иконка) | admin-models3d-list.js | openFileManager уже вызывается |
| Материалы 3D | admin-models3d-materials.js | openFileManager уже вызывается |
| Редактирование элемента каталога (иконка) | catalog-item-edit.html | Пытается использовать window.openFileManager / parent.openFileManager |

### Страница admin-new.html (бандл + делегирование в admin-new-extra-3.js)
Перехват в **capture** по одному обработчику на document: кнопки «Выбрать» / «Выбрать изображение», любой клик в превью, плейсхолдеры иконок.

| Вкладка/раздел | Что перехватывается | Статус |
|----------------|---------------------|--------|
| **Материал (material-item-edit)** | Кнопки material-texture-upload-btn, material-normal-map-upload-btn, material-roughness-map-upload-btn; превью material-texture-preview, material-normal-map-preview, material-roughness-map-preview; блок иконки material-item-icon-placeholder, material-item-icon-preview-wrapper | ✅ Перехват |
| **Кромка (edge-item-edit)** | Кнопки edge-texture-upload-btn, edge-normal-map-upload-btn, edge-roughness-map-upload-btn; превью edge-texture-preview, edge-normal-map-preview, edge-roughness-map-preview; блок иконки edge-item-icon-placeholder, edge-item-icon-preview-wrapper | ✅ Перехват |
| **MKM (материалы ключей и т.п.)** | Кнопки mkm-texture-upload-btn, mkm-normal-upload-btn, mkm-roughmap-upload-btn; превью mkm-texture-preview, mkm-normal-preview, mkm-roughmap-preview | ✅ Перехват |
| Фасад (модель, иконка, normal) | Другие id в бандле | Пока не в делегировании — добавить по аналогии при необходимости |
| Импорт (xlsx и т.д.) | Отдельные input type=file | Обычно оставляют системный диалог или подключают FM по желанию |

### Файлы, которые не используются на admin-new.html
- **admin-materials-items.js** и **admin-edges-items.js** в этой странице не подключаются (используется бандл).  
  Код с openFileManager в них на текущей странице не выполняется; он мог бы пригодиться, если когда-нибудь перейти на подключение отдельных модулей вместо бандла.

## Сложность и выводы

1. **Один бандл** — всё в одном файле, правки через замены строк рискованны (скобки, кавычки, парсер Vite).
2. **Делегирование** — безопасный способ «везде открывать наш FM» для всех мест с иконкой-папкой в известных блоках, без правки бандла.
3. **Расширение на «во всём проекте»:**  
   - Для admin-new.html — дополнять список селекторов в admin-new-extra-3.js (новые контейнеры/иконки, которые должны открывать FM).  
   - Остальные страницы/скрипты — уже используют openFileManager там, где он подключён; при появлении новых форм с файлами — вызывать там `openFileManager` (или вешать такое же делегирование на свою страницу).

Если нужно, можно следующим шагом пройти по бандлу и выписать все id/классы, где ещё вызывается `input.click()` или есть `type="file"`, и решить по каждому: добавить в делегирование или оставить системный диалог.
