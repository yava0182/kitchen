## Исходные данные сценария

| Параметр | Значение |
|----------|----------|
| Стена ряда | `back` (типичный прямой ряд) |
| Пивот секции (стена) | условно `W = 0` мм вдоль оси глубины |
| Знак «в комнату» | `sign = +1` → рост **+Z** от стены в комнату (`kitchenIntoRoomSign`) |
| Глубина столешницы Dwt | **600** мм |
| Глубина корпуса D | **550** → затем **500** мм |
| Канон стека | front setback **40** мм; rear overhang ≥ **10** мм |

Файлы канона: `js/kitchen/kitchen-depth-stack.js` (шапка + `enforceKitchenDepthStackOnModule`), `js/kitchen/kitchen-manufacturing-profile.js` (`resolveBaseCarcassDepthMm`, константы 40/10).

### Система координат (**код**)

- Мир Three.js: мм как единицы сцены комнаты.  
- Для стены `back`: плоскость стены = `section.group.position.z`; глубина вдоль **Z**.  
- «Зад» корпуса = меньший Z при `back` (`bb.min.z`); «перед» = `bb.max.z`.  
- Стены `left`/`right`: та же логика на оси **X**.  
- В таблицах ниже: **W = 0**, **+Z в комнату** — нормализованная модель; абсолютные мировые координаты на живой сцене = W_секции + эти значения.

### Живая сцена (**сцена**)

На момент проверки вкладка Clodis: `http://localhost:8100/?v=20261028-bands15`, step≈1, **секций 0, мебели НМ 0**.  
`measureKitchenNmDepthReport('back')` → `{ ok: false, modules: [] }`.  

**Полноценный e2e с измерением bbox без размещения мебели / изменения проекта — невозможен.** Ниже координаты — **расчёт по алгоритму кода**, не факт с мешей.

## Проверка 1. Базовая геометрия (Dwt=600, D=550, offsets 0/0)

### Расчёт стека (**код** + **формула**)

```
worktopFront     = W + Dwt                    = 0 + 600 = 600
targetCarcassFront = worktopFront − 40        = 560
carcassBack      = targetCarcassFront − D     = 560 − 550 = 10
rearOverhang     = Dwt − 40 − D               = 10
frontSetback     = 40
```

| Величина | мм от стены W | Источник |
|----------|---------------|----------|
| Задняя плоскость корпуса | **10** | формула / код enforce |
| Передняя плоскость корпуса | **560** | формула / код |
| Перед столешницы | **600** | формула / код |
| Расстояние до стены (wall gap) | **10** | = rear overhang |
| Задний свес столешницы над корпусом | **10** | wall → carcassBack |
| Передний свес столешницы | **40** | carcassFront → worktopFront |

### Перед фасада (**код**, без живого меша)

- `measureKitchenNmDepthReport` считает `doorFront` по **полному** bbox группы и `doorProtrusionBeyondCarcassMm = doorFront − carcassFront`.  
- Точная величина зависит от дерева (толщина фасада / ручки, обычно порядка толщины детали фасада).  
- **Не измерено на сцене.** Ожидание: фасад **впереди** корпуса на толщину полотна (часто ~16–22 мм), т.е. ≈ **576…582** при W=0 — **предположительно**, не подтверждено.

Корпусный bbox для стека: `computeFurnitureCorpusLayoutWorldBBoxNoAo` (`forDepthScale: true`) — фасад/AO исключаются из якоря корпуса (**код**).

## Проверка 2. `rearOffsetMm=50`, `frontOffsetMm=0`

### Алгоритм (**код** `applyKitchenModuleOffsetsAfterStack`)

После канонического place:

```
deltaMm = rearOffset − frontOffset = 50 − 0 = 50
сдвиг группы: +sign * 50  (весь модуль в комнату)
D корпуса не меняется
```

Затем stamp стека пересчитывается так, чтобы **канонический** rear в ud остался без «накопления» offset:

`stackRear = wallGapMeasured − rearOffset + frontOffset` → снова **10**.

### Таблица после offset (**формула**)

| Величина | До (0/0) | После (50/0) | Δ |
|----------|----------|--------------|---|
| D корпуса | 550 | **550** | 0 |
| Перед корпуса | 560 | **610** | +50 |
| Зад корпуса | 10 | **60** | +50 |
| Перед столешницы (стек/оверлей) | 600 | **600** (не двигается offsets) | 0 |
| Wall gap (зад→стена) | 10 | **60** | +50 |
| Зазор столешка−перед корпуса | +40 | **−10** | −50 |

### Выводы проверки 2

| Вопрос | Ответ | Доказательство |
|--------|-------|----------------|
| Весь модуль на 50 мм? | **Да** (rigid shift) | код delta = rear−front |
| Меняется ли D? | **Нет** | write offsets не трогает carcass |
| Фасад с корпусом? | **Да** (дети группы) | код shiftGroupAlongDepth на group |
| Передняя линия vs столешка | Перед корпуса уезжает **в комнату на 50**; относительно столешки setback становится **−10** (корпус/фасад выступают за торец столешки) | формула; оверлей столешки **не** читает rearOffset (**код** grep kitchen-run-overlays) |
| Повторный enforce | Offsets читаются снова → тот же net shift; stamp rear канонический | код enforce |

**Ограничение:** `rearOffsetMm` — это **не** «увеличить щель у стены, оставив перед под столешкой». Это сдвиг всего модуля относительно уже поставленного стека (столешка остаётся на W+Dwt).

Повторный enforce **не** накапливает 50+50, потому что каждый раз: абсолютный place на target front → один delta (**код** комментарий «без накопления»).

## Проверка 3. D: 550→500 при `rearOffsetMm=50`

### Путь (**код**)

`rebuildForCellDepthMm` → `resolveBaseCarcassDepthMm` → `rebuildFurnitureGroupForSectionResize` (Z=500) → `alignBackToWall` = `enforceKitchenDepthStackOnModule` → снова offsets.

`ud.rearOffsetMm` rebuild **не сбрасывает** (**код**).

### Плоскости (**формула**)

Канон при D=500: front=560, back=60, rearOverhang=60.  
+ net 50: front=**610**, back=**110**.

| | D=550, rear=50 | D=500, rear=50 |
|--|----------------|----------------|
| Перед корпуса | 610 | **610** (сохранён) |
| Зад корпуса | 60 | **110** (ушёл **в комнату**) |
| Wall gap | 60 | **110** |
| D | 550 | **500** |
| Канон. rear stamp | 10 | **60** |

### Детали / крепёж (**код**, сцена не гонялась)

| Вопрос | Статус |
|--------|--------|
| Параметрический rebuild деталей | **да** — `rebuildFurnitureGroupForSectionResize` с новым Z |
| Задний offset stamp | **сохраняется** на ud |
| Перед после смены D | якорь стека + тот же net → **та же** абсолютная передняя плоскость |
| Зад | отодвигается от стены (щель растёт) |
| Стыки / крепёж | после rebuild: ClodisBuilder → `__cldApplyJointFittingHoles`; также `__cldRepositionJointSchemeFurniture` в depth path (**код**). **На сцене не проверено.** |

## Проверка 4. Комбинации — таблица плоскостей

Условия: W=0, sign=+1, Dwt=600.  
Колонки — мм. **формула** (зеркало enforce).

| # | D | rearOff | frontOff | net | Перед корпуса | Зад корпуса | Wall gap | Перед столеш. | Setback столеш.−корпус | Канон rear stamp |
|---|----|---------|----------|-----|---------------|-------------|----------|---------------|-------------------------|------------------|
| A | 550 | 0 | 0 | 0 | 560 | 10 | 10 | 600 | +40 | 10 |
| B | 550 | 50 | 0 | 50 | 610 | 60 | 60 | 600 | **−10** | 10 |
| C | 500 | 50 | 0 | 50 | 610 | 110 | 110 | 600 | **−10** | 60 |
| D | 500 | 50 | 50 | 0 | 560 | 60 | 60 | 600 | +40 | 60 |
| E | 500 | 0 | 0 | 0 | 560 | 60 | 60 | 600 | +40 | 60 |

### Независимость rear / front (**код** + **формула**)

```
deltaMm = rearOffsetMm − frontOffsetMm
```

- На положение влияет **только net**.  
- Строки **D** и **E** совпадают по плоскостям при разных (50,50) vs (0,0).  
- **Не** две независимые пользовательские «щели» (зад отдельно и перед отдельно с фиксацией обеих кромок): при фиксированном D это один DOF.  
- Пара frontOffset нужна, чтобы **компенсировать** rear (вернуть net к 0), либо сдвинуть модуль **к стене** (front > rear → net &lt; 0).

## Итог по сценариям

### Что уже работает (**код** / **формула**)

1. Канон Dwt=600 / D=550 → перед 560, зад 10, свесы 40/10.  
2. Смена D при net=0: перед корпуса остаётся на W+(Dwt−40); зад двигается.  
3. Offsets сохраняются на ud и в fixture; API `__cldSetKitchenModuleOffsetsMm` пишет stamps и вызывает enforce.  
4. После depth rebuild путь снова через enforce → net offset применяется повторно; перед при том же net стабилен.  
5. Параметрический rebuild Z для кухни (не scale).  
6. Цепочка крепежа после rebuild существует в коде.

### Ограничения / поведение, важное для продукта

1. **UI карточки не задаёт rear/frontOffset** (только API).  
2. Offsets = **один** rigid shift (net); не две независимые кромки.  
3. Столешка **не** едет с `rearOffsetMm` → при net≠0 ломается канон «перед корпуса = столешка−40» (даже отрицательный setback).  
4. «Отступ от стены» в UI НМУ ≠ `rearOffsetMm`.  
5. `measureKitchenNmDepthReport.ok` сравнивает wallGap с **каноническим** rear **без** учёта offsets → при active offsets флаг `ok` будет false даже при корректной работе (**код** ~603–605) — ложный «фейл» диагностики.

### Ошибки / противоречия (с доказательством)

| # | Наблюдение | Доказательство |
|---|------------|----------------|
| 1 | rearOffset≠0 сдвигает перед за линию столешки | формула B/C; overlays без rearOffset |
| 2 | (50,50) ≡ (0,0) по геометрии | формула D vs E |
| 3 | Diagnostic `ok` игнорирует offsets | measureKitchenNmDepthReport |

Не классифицируется как «баг» без ТЗ: возможно, offset задуман как временный сдвиг всего блока. Но для сценария «+50 от стены, сохранив перед под столешкой» **текущий API недостаточен** — нужен рост канонического rear (смена D или Dwt / другая модель), а не `rearOffsetMm` alone.

### Что требует доработки (без проектирования решения здесь)

1. Продуктово: UI и смысл «отступ от стены» vs `rearOffsetMm`.  
2. Согласовать offsets со столешкой (если нужен сохраняемый front setback 40).  
3. Живой e2e: place НМ → set offsets → rebuild D → measure → save/load → CFRN.  
4. Поправить или документировать критерий `ok` в measure-отчёте при offsets.

### Что не проверено на мешах

- Фактический bbox / фасад protrusion.  
- Повторный enforce на живом объекте.  
- Пересчёт joint positions числами.  
- CFRN dump.  
- Save/load round-trip.
