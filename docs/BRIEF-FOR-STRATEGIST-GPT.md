## Роли

| Роль | Делает | Не делает |
|------|--------|-----------|
| **Человек** | Приёмка да/нет, выбор агента в UI, «принято / слой закрыт» | Не обязан писать код |
| **GPT-стратег** | Узкие задачи по шаблону, обсуждение канона, порядок слоёв | Не пишет большой diff в репо; не включает субагентов Cursor сам |

Связка: стратег → формулирует задачу человеку/в чат Auto → Auto делает → человек да/нет → стратег следующая узкая.

## Правила, чтобы не сыпалось (обязательны для стратега)

1. **Один слой = одно сообщение Auto.** Не «и ещё фасады / цену / угол».
2. Шаблон задачи:

```
Слой: …
Модуль: …
Сейчас: …
Должно: … (число или одно поведение)
Проверка: ?v=… / bust …
Не трогать: …
```

3. После ответа Auto: только **да/нет** по чеклисту. Если нет — скрин + «не так: …».
4. «Принято, слой закрыт» — прежде чем новый слой.
5. Без костылей: не просить scene-overlay / миллиметровые сдвиги «под скрин» / JSON-хаки вместо модели.
6. **Админка → комната:** что в дереве модуля — то в сцене. Не наоборот.
7. Углы L/U / НМУ — **отдельный** замороженный канон; не мешать с сеткой 600 и накладками в одной задаче.
8. Платных агентов/субагентов Cursor **включает только человек в UI**, не стратег и не Auto.

Плохо: «сделай как в рефе», «всё сломалось», «почини угол и заодно накладки».  
Хорошо: «прямая 2000 мм: жертва zi=2 = 200, края 600; карандаш 600→900 жмёт только жертву».

## A. Прямая секция — ячейки 600 + жертва (приниматель)

**Статус:** сделано и в rule `.cursor/rules/straight-600-sacrifice.mdc`. Углы L/U этим правилом **не** трогаем.

### Имена

- **Жертва = приниматель** — одна ячейка (`sacrificeZoneIndex`), куда уходит delta карандаша ширины.
- Не путать с «ближайшим соседом» только для геометрии накладки: карандаш ширины на прямой **не** размазывает по соседям.

### Авто-сетка (пустая прямая / без ручного карандаша)

- `parts = ceil(W / 600)`
- Ширины: `N × 600` + **один** остаток в жертве (если W не кратно 600).
- Жертва **не на краю**: **справа от центра**
  - нечёт parts (3,5…): `center = floor(n/2)`, жертва = `center + 1` (не сама центральная);
  - чёт parts (2,4…): жертва = `n/2`.
- Пример: **2000** → `600 | 600 | 200 | 600`, жертва **zi=2**.
- Ровно **1800** → `3×600`, жертва помечена (zi=2 при parts=3).
- Код: `buildKitchenStraight600SacrificePlan`, `kitchenStraightSacrificeZoneIndex`, `applyKitchenStraight600SacrificeWidths` в `js/kitchen/kitchen-section-layout.js`.

### Карандаш ширины (прямая)

1. Рост ячейки → мм **только с жертвы**.
2. Жертвы не хватает → жертва **схлопывается** (parts−1), приниматель на **соседа** (предпочтительно слева от бывшей жертвы); дальше добор с новой жертвы.
3. Ужатие ячейки → лишнее **всё в жертву**.
4. Редактируемую не доить, пока есть другая.

### Запрещено без смены канона

- Пропорциональный balancer «по соседям» на прямой.
- Несколько жертв / размазать −Δ по свободным.
- Лезть в L/U спец-ячейки этим алгоритмом.

## B. Накладки (side panels / overlay 16 мм)

**Статус:** основной канон колонки принят человеком; мелочь «пенал при смене антресоли» — **отложена** («репу чесать»).  
Rule: `.cursor/rules/side-panels-column-pad.mdc`, код: `kitchen-side-panels-overlay-api.js`, pad OR: `getKitchenColumnOverlayPadSidesMm`.

### Модель

- Накладка **снаружи** корпуса, 16 мм на сторону (L и/или R → pad 16 или 32).
- **Ячейка = корпус + pad** (корпус не жмём под накладку).
- **Pad колонки** = OR сторон у **пенал ∪ MID ∪ TOP** в одной `zoneIndex`.
- **Плательщик** — кто первым ставит сторону: ячейка += 16, компенсация с жертвы/соседа по footprint.
- **Наследник** — сторона уже в pad колонки: сетку второй раз не раздуваем; `корпус = ячейка − pad_колонки`.
- Пенал не единственный плательщик: антресоль может оплатить первой; пенал потом — наследник (и наоборот).

### Кто какие пояса пишет

| Плательщик | Пояса |
|------------|--------|
| Пенал (tall) | BASE + MID + TOP |
| НШ1 / НШ2 (mid/top) **без** пенала в zi | только MID + TOP (BASE/НМ снизу **не** раздувать) |
| НШ при **пенале** в той же zi | тянет и BASE (вся колонка) |
| НМ | только BASE (+ столешка по ширине ячейки); **не** наследник верхней накладки |

### Rebuild pad

- НШ / НМ: **ownPad** only (без своей накладки корпус = вся ячейка).
- Пенал: `max(ownPad, columnPad)`.

### Взаимозаменяемость

- **НШ1 ↔ НШ2** в одной колонке: mid↔top align, `nextWidthsByBand`, без разъезда поясов.
- **Пенал ↔ антресоль**: взаимозаменяемы как плательщик/наследник; при delta≈0 но пояса не на target — сначала **выровнять**, потом наследник.

### Принято / прогнано человеком

- ownPad у навеса/антресоли;
- НШ1↔НШ2;
- пенал L/R, пенал+антресоль (в целом ок);
- верх без пенала не раздувает НМ снизу;
- слой накладок по канону **закрыт**, с оговоркой ниже.

### Отложено

- Край: поведение **пенала, когда меняют/трогают антресоль** — не чинить сейчас, отдельная сессия.
- Если всплывёт «только верх → −32 / разъезд соседей» — отдельный узкий слой.

### Глубина НШ / антресоли (не ломать заодно)

- НШ1: глубина корпуса **20…45 см**, отступ от стены отдельно.
- НШ2: **20…70 см**; над пеналом по умолчанию deep ≈ D пенала; ручная смена → custom+lock.
- Человек сказал: **оставить как есть**, если снова «не меняется» — отдельный баг с скрином, не мешать с сеткой.

## E. Как стратег пишет задачу в чат Auto (пример)

```
Слой: сетка прямой / накладки / … (одно)
Модуль: …
Сейчас: …
Должно: …
Проверка: открыть ?v=… (или «после правки — bust от Auto»)
Не трогать: фасады, UI, цену, столешку, НМУ, угол
```

После зелёной приёмки — следующая **одна** тема.  
Если 2–3 сессии без зелёного — предложить смену подхода (порт узкого слоя из рефа), не ещё один миллиметровый патч.
