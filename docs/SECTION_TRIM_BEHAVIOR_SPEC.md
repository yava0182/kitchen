### Как пользоваться при поломке

1. Определить ситуацию: **§4.0** (пустая / частичная занятость прямой), **§4 / §4.1** (геометрия при создании) или **§6–§7** (мебель / переходы).
2. Найти № детали в **§3** и строку в таблице §4 или §6.
3. Открыть указанную функцию в коде (колонка «Где в коде») и сравнить с таблицей.
4. После исправления кода — **обновить этот документ**, если фактическое поведение изменилось (колонка «Сейчас в коде» в §7).

## 3.1. Синие метки № обклада на сцене (UI)

Оверлей поверх 3D: на каждой видимой детали обклада (`isSectionTrimFacadeMesh`, не `isEdge` / `isUncutEdge`) — синий бейдж с **№ из каталога** (как в админке «Обклад», см. §3). Это **не** номера кромок деталей мебели (`spec.show_index` в JSON шкафа).

**Уже в коде** — раздел для восстановления, не задача.

| Параметр | Эталон |
|----------|--------|
| По умолчанию | **Выключено** — меток нет после загрузки |
| Включение | `window.__CLD_SHOW_TRIM_PART_LABELS = true` (только явное `true`) |
| Шаги комнаты | Метки возможны на шагах **2–6** (`currentRoomStep`); на других шагах не показываются даже при `true` |
| Проверка видимости | `isTrimPartNumberLabelsVisible()` в `section-trim-edges.js` |
| Пересборка меток | `refreshTrimPartNumberLabels(scene)` — сначала `clearTrimPartNumberLabels`, затем обход сцены и `createDimensionLabel` |
| После обклада / шага | `window.refreshTrimPartNumberLabels` (из `furniture-manager.js`): `section-transition-manager` после `rebuildWallTransitions`, `room-steps` при смене шага |
| Позиция в кадре | `scene-icons.js` — цикл проекции `trimPartNumberLabels` (как размеры секции/мебели) |

### 3.1.1. Кнопка на сцене

| Параметр | Эталон |
|----------|--------|

### 3.1.2. Восстановление при поломке

1. Метки видны без клика → проверить, что нигде не выставляется `__CLD_SHOW_TRIM_PART_LABELS = true` по умолчанию; в `isTrimPartNumberLabelsVisible` условие **`!== true` → скрыть**.
2. Кнопка не переключает → обработчик в `addSceneIcons`, наличие `window.refreshTrimPartNumberLabels`.
3. Метки «залипают» после выкл → `refreshTrimPartNumberLabels` должен вызываться при выкл (очистка в начале функции).

**Сверка §4 / §4.1:** фразы «эталон на сцене: метки **1**, **3**…» относятся к **геометрии** обклада; сами бейджи на экране — только при включённом §3.1.

## 4.0. Прямая секция: видимость рамки и доборы по занятости (2026-09-18)

> **Правило Cursor (always):** `.cursor/rules/straight-section-trim-by-occupancy.mdc`  
> **Не путать с окном:** у окна пустая ячейка может **не создавать** меши; у прямой меши №1/3/5–12 **строятся** (для insets / 5 см), но **скрываются**, пока нет мебели.

### 4.0.1. Инварианты

| Инвариант | Правило |
|-----------|---------|
| Разметка ячеек | Не менять под обклад |
| Отступ 5 см от стены | Всегда в offsets / insets; **не** зависит от того, какой модуль стоит |
| Скрытие рамки | Только `visible=false`, **не** `remove` боковин (иначе поедут bounds) |
| Доборы | Появляются **по факту** посадки модуля и правилам §6 для его типа |

### 4.0.2. Пустая прямая

| № | Видимость | Меш |
|---|-----------|-----|
| 1, 3, 5–12 | **скрыты** | на месте |
| Разметка / 5 см | как §4 / §4.1 | — |

**Код:** `applyStraightFrameVisibility` — нет мебели → всё frame `visible=false`.

### 4.0.3. Один модуль

| Тип | Верх №1 | Цоколь №3 | Бок №5–12 |
|-----|---------|-----------|-----------|
| Шкаф (высокая / ниша) | на **ширину шкафа** по U | под шкафом | по отступу стены (§4.1): ≤5 → планка, >5 → накладка; виден у края с модулем |
| Комод/тумба (&lt;1500) | потолочной №1 **нет** (§6.2); топ корпуса / AutoTop | под комодом | по §6.1 / §6.3 |
| `wall_hung_high` | №1 на ширину навеса | нет | §6.7; AutoBottom снизу |
| `wall_hung_low` | потолочной №1 **нет**; AutoTop | нет | §6.7 |
| Пустые ячейки рядом | нет рамки | нет | нет (скрыты) |

**Код:** `_splitSectionHorizontalPlanks` — топ из **tall** U; цоколь из occupied **без** merge tall↔low.

### 4.0.4. Шкаф + комод

| Деталь | Эталон |
|--------|--------|
| №14 SideCap | между шкафом и комодом |
| №1 / №13 | только над шкафом; торец у **внутренней** стороны накладки стыка |
| №3 цоколь | **разрыв** на накладке: сегмент шкафа + сегмент комода |
| №15 TopCap / топ комода | от стыка до края комода; **не** наезд на накладку |

**Код:** split (tall / band) → `_adjustTopPlankForLowFurniture` → SideCap/TopCap → `applyStraightFrameVisibility` (**не** включать снова length-топ, если есть `TopPlankSegment`).

### 4.0.5. Запрещено при правках

- Включать всю рамку секции при `sectionHasPlacedFurniture === true`.
- Удалять SideOverlay/SidePlank ради «пустого» вида.
- Менять partSize / маркеры ячеек «заодно» с обкладом.

## 4.1. Прямая секция с отступом от боковой стены

`front` / `back`, без мебели, без L-угла, в `sectionData.offsets` задан **leftMm** и/или **rightMm** (логические отступы секции от стен комнаты).  
Эталон геометрии (пример, бейджи — §3.1): отступ слева **50 см** → **1**, **3**, **9**, **10**; ширина секции по стене (напр. 400 см), высота ≈ 250 см.

**Уже в коде** — `addSidePlanksIfNeeded` + подрезка горизонталей в том же проходе.

### 4.1.1. Выбор детали на левом / правом торце

Источник отступов: `getSectionOffsetsMm(sectionData)` → `leftMm`, `rightMm`.  
Порог прилегания: **5 мм** (`wallEps` в коде = `TRIM_ROOM_GAP_THRESHOLD_MM`).

| Отступ торца (`leftMm` или `rightMm`) | Деталь на торце | № на метке | Толщина по U |
|--------------------------------------|-----------------|------------|--------------|
| **≤ 5 мм** (прилегание к стене) | `SidePlankLeft` / `SidePlankRight` | **5** / **6** | 50 мм |
| **> 5 мм** (зазор до стены) | `SideOverlayLeft` / `SideOverlayRight` | **9** / **10** | 16 мм |

Симметрично для левого и правого торца; на одной секции может быть **9 слева + 10 справа** (оба отступа), или **9 + 6**, если справа прилегание.

### 4.1.2. Вертикали при отступе (№9, №10)

| Параметр | Эталон |
|----------|--------|
| Высота | **В потолок:** `size.y`, как у №5/6 (`fullHeight = height`) |
| Положение по Y | Центр `y = size.y / 2` (от пола секции до верха) |
| Геометрия | `16 × size.y × depth` (накладка в плоскости фасада) |
| Позиция по X | У внутреннего торца секции: `innerLeftX + 8` / `innerRightX − 8` (половина 16 мм) |

После `rebuildWallTransitions`: без мебели — полная высота; **с мебелью** накладки и планки 50 мм — **одна** логика (**§6.3**, `_adjustVerticalTrimHeightsForWall`), повтор после кромок шага 5 (`_reapplyVerticalTrimHeightsForAllWalls`). `prepareTrimMeshObkladVisual` **не** откатывает `_trimmedVerticalForFurniture`.

### 4.1.3. Верхняя планка и цоколь (№1, №3) при отступе

Два разных торца — разное правило длины по U:

| Торец | Вертикаль на торце | №1 / №3 по U |
|-------|-------------------|--------------|
| Отступ > 5 мм | Накладка №9 / №10 (`SideOverlay`) | До **внешней** грани накладки (`cut = 0`) |
| Прилегание ≤ 5 мм | Планка №5 / №6 | До **внутренней** грани планки (`cut = 50 мм`) |
| Торцевой шкаф вместо накладки | `EndCabinetFacadeOverlay` + модуль | `cut = 0` + **extend** на `getEndCabinetReserveMm` (цоколь с inset фасада) |

| Параметр | Эталон |
|----------|--------|
| Эффективная ширина при накладке | `width` (без выреза 16 мм) — концы заподлицо с внешней гранью №9/№10 |
| Эффективная ширина при планке 50 | `width − cutLeft − cutRight` |
| При торцевом | `width + extendLeft + extendRight` (− plinth inset у №3) |
| Высота / толщина | №1: 50 мм у верха; №3: 100 мм у пола — **как без отступа**, меняется только длина по U |

После мебели (§6.6): крайние сегменты №1/№3 снова расширяются на 16 мм при `kind === 'overlay'`; при торцевом — на резерв (как при создании).

Код: `addSidePlanksIfNeeded` (`cutLeft` / `cutRight` / `extend*`); `_getZoneEntriesForHorizontalPlankSplit`.

### 4.1.4. Что не меняется при отступе (пока нет мебели)

| Тема | Эталон |
|------|--------|
| Мебель | Нет → переходы не подрезают вертикали по высоте мебели |
| Угловая L-секция | Не §4.1 — свои suppress/№2, №4, №7, №8 |
| С мебелью | №1/№3 → §6.2; №5–10 → §6 |

**Точка входа:** `section-manager.js` — `addDefaultTopPlank`, `addDefaultBottomPlank`, `addSidePlanksIfNeeded` (ветка `wallName === 'front' || 'back'`).

## 4.2. Торцевой шкаф на торце секции (единый inset с §4.1)

Когда на торце с зазором выбран **торцевой шкаф** (`sectionData.endCabinets[side].mode === 'cabinet'`):

| Параметр | Эталон |
|----------|--------|
| `SideOverlayLeft/Right/…` на торце ряда | **Не создаётся** (`shouldSuppressSideTrimForEndCabinet`) — шов не «накладка у стены» |
| Inset ряда у торцевого | **16 мм** только если у края **низкий** модуль (тумба) — место под SideCap; шкаф той же высоты → **0** (вплотную) |
| Стык **тумба ↔ торцевой** | `TransitionSideCap` + `TransitionTopCap` (как шкаф↔тумба); граница = `outerMinU`/`outerMaxU` |
| Стык **шкаф ↔ торцевой** (≈ равная высота) | Без SideCap, inset 0 |
| Фасадная накладка торцевого | `EndCabinetFacadeOverlay_*` — плоскость фасадов на корпусе торцевого (не §6.3) |
| Модуль торцевого | Вне зон (`getEndCabinetSlot`), **не** через `zoneIndex` |

### 4.2.1. Единый контракт inset'ов (фаза A)

**Источник правды:** `js/sections/section-edge-trim-insets.js`

| Функция | Назначение |
|---------|------------|
| `getSectionEdgeTrimInsets(sectionData, 'min'\|'max')` | Inset одного логического торца ряда по U |
| `getPhysicalSideTrimInsetMm(sectionData, wallName, side)` | Inset для `left`/`right`/`front`/`back` (маркеры) |
| `computeSectionInnerBoundsU(sectionData)` | `innerStartU`, `innerEndU`, `innerWidthU` для layout |
| `detectSectionEdgeTrimMeshes(group, wallName)` | Факт: `SidePlank` / `SideOverlay` / `EndCabinetFacadeOverlay` |

**Порядок:** если на group есть mesh — по mesh; иначе предсказание по `offsets` + `endCabinets`.  
**Потребители:** `computeSectionLayout` (`section-manager.js`), `cabinet-markers.js`.  
**Отладка:** `window.__clodisComputeSectionInnerBoundsU(sectionData)` в комнате.

## 5. Типы мебели (для таблиц правил)

| `__placementKind` | Смысл | «Высокая» для обклада / стыка |
|-------------------|--------|-------------------------------|
| `floor_in_niche` | Шкаф в нише секции | **Всегда да** (до потолка секции) |
| `standalone_floor` | Тумба / комод на полу | **Низкая** (&lt;1500); стык SideCap как низкий |
| `wall_hung_low` | Нижний навес (к полу, фикс. высота) | **Низкая** (как комод): AutoTop, без потолочной №1 над ним |
| `wall_hung_high` | Верхний навес (к потолку) | **Высокая** для стыка tall↔low; потолочная №1 над ним; AutoBottom снизу корпуса |
| `wall_hung` | Legacy alias | = `wall_hung_high` |

### 6.3. Правило «зона по U» (алгоритм в коде)

Для каждой вертикали `SidePlank*` / `SideOverlay*` на прямой секции (`_isStraightSectionForTrimHeight`):

1. World-span детали по U из bbox mesh (`_worldUSpanFromBox`).
2. Кандидаты мебели: `_collectFurnitureForVerticalTrim` — тот же `sectionId` **или** bbox пересекает span вертикали по U **или** span секции по U (ε 28 мм).
3. Торец по **имени mesh** (`_verticalTrimLogicalEdge`: `SideOverlayLeft` → min, `SidePlankRight` → max и т.д.).
4. На торце: scope = `_filterFurnitureNearSectionUEdge` (шкаф в центре **не** режет правую планку / левую накладку).
5. В scope, пересечение полосы вертикали по U: **высокая** → `size.y`; иначе **низкая** → `max(topLocalY)`.
6. Нет пересечения по полосе → `_pickEdgeFurniturePreferLow(scope, edge)`; высокий на торце → `size.y`.
7. Иначе → `size.y`.

После кромок шага 5: `prepareTrimMeshObkladVisual` **не** сбрасывает высоту, если `userData._trimmedVerticalForFurniture`; повтор — `__clodisReapplyVerticalTrimHeights` / `_reapplyVerticalTrimHeightsForAllWalls`.

> Шаг 6 — кейс «отступ 500 мм + тумба справа»: левая №9 не пересекает bbox тумбы по U, но на торце и берёт высоту **крайней** тумбы.

**Вызов:** в конце `rebuildWallTransitions` → `_adjustSideOverlayForLowFurniture` → `_adjustVerticalTrimHeightsForWall`. Перед размещением мебели: `__clodisUpdateFurnitureInSection` → `rebuildAllTransitions` (`placePendingFurniture`).

### 6.4.1. Объединение топов тумб (AutoTopCap) — эталон

**Уже в коде** — восстановление, не backlog. Накладки №9–12, SideCap, планки — **не меняются**.

| Правило | Эталон |
|---------|--------|
| Кому | Все низкие тумбы секции (`< 1500 мм`), **включая** у шкафа |
| Цепочка | Подряд идущие сегменты `type: 'module'` в `_layoutCache` одной секции |
| Разрыв цепочки | Только `type: 'cap'` (16 мм между шкафом в нише и тумбой). Сегмент шкафа в layout **не** рвёт цепочку |
| Лимит 2750 | Сумма ширин зон чанка: `endU - startU` (напр. 1085+1085 = **2170**) |
| Разбиение | Жадно **от шкафа** (min U): merge с первой тумбы у cap, до 2750 мм; **остаток** — плита(ы) на дальнем торце; рез только между соседними зонами тумб |
| Геометрия плиты | Один `TransitionAutoTopCap` на `startU…endU` чанка (+ торцевые планки чанка при необходимости) |
| Дубль у шкафа | Если в merge вошли **≥2** тумбы, `TransitionTopCap` на этой тумбе **удаляется** (`_removeTransitionTopCapsForMergedStandalones`) |
| Одна тумба у шкафа | Только `TransitionTopCap` (узкий по bbox), без общего merge |

#### Примеры (тумба 1085 мм, расстановка справа → налево)

| Поставлено | Топы |
|------------|------|
| 1-я (у шкафа) | 1085 |
| 2-я | **2170** (одна плита) |
| 3-я | 1085 + 1085 > 2750 → новая плита на 3-й; 2-я остаётся в паре с 1-й |
| 4-я | **2170** (1-я + 2-я у шкафа) + **2170** (3-я + 4-я на дальнем торце) |

При 4 тумбах без шкафа в той же цепочке: **2170 + 2170** (две плиты, та же логика с min U).

#### Алгоритм (код)

1. `__clodisComputeSectionLayout(sec)` перед сборкой.
2. Обход `segments`: модули с низкой мебелью → цепочка; `cap` → `flush`; шкаф без footprint → `continue`.
3. `_partitionLayoutChainByMaxU` — жадно с начала цепочки (min U, у шкафа).
4. `_emitLayoutTopCapChunks` → `_createAutoTopCapFromFootprint`.
5. `_removeTransitionTopCapsForMergedStandalones` — снять дубль TopCap.

**Вызов:** конец `rebuildWallTransitions`, после `_adjustTopPlankForLowFurniture`.

**Функции:** `_buildMergedAutoTopCapsOnWall`, `_mergeTumbaTopsOnSection`, `_partitionLayoutChainByMaxU`, `_extendUSpanForChunkPlanks`, `_computeExtendedTopFootprint`.

**Торец топа у накладки:** `_extendUSpanForChunkPlanks` и `_computeExtendedTopFootprint` — выступ **1 мм** за **внешнюю** грань накладки (`outerMinU − 1` / `outerMaxU + 1`), по `division.sectionStart` / `sectionEnd` (не `zoneIndex === parts−1`).

1. **2 тумбы + шкаф:** один `TransitionAutoTopCap` **2170** (зоны 1+2); `TransitionTopCap` на 1-й снят.
2. **4 тумбы + шкаф:** **2170** (1–2 у cap) + **2170** (3–4); не отдельная плита только на 1-й.
3. **Отступ слева >5 мм:** `SideOverlayLeft` + высота по тумбе; `SidePlankRight` у шкафа — полная; merged топ +1 мм слева/справа у накладок секции.
4. **Одна тумба у шкафа:** только `TransitionTopCap` (узкий), без merge ≥2.

### 13.5. Порядок восстановления при поломке

1. Прочитать **§13.1** по симптому.
2. Ctrl+F5, убедиться в актуальном `?v=` в Network.
3. `__clodisRebuildAllTransitions()`, смотреть красные ошибки.
4. Сверить поведение с **§9** (строки F, G, J) и **§6.4.1**.
5. Сравнить код с **§7**; при расхождении — править код **или** обновить §7/§12 (§11).

### 13.7. Изменение размера секции и отступов (мебель + зоны)

**Симптом:** после смены ширины/отступов в модалке секции шкафы/тумбы **наезжают** друг на друга, как будто layout не пересчитан.

**Цепочка (эталон):**

1. `updateSectionSize` — пересоздаёт планки/накладки, `sectionData._relayoutZonesFromPosition = true`.
2. `computeSectionLayout` — новые `sectionStart`/`sectionEnd`, `moduleWidthsMm`, сегменты `startU`/`endU`.
3. `updateFurnitureInSection` — ширина зоны из сегмента, **позиция** по `startU`/`endU`, scale от эталонного bbox (не накопительный `*=`).

**Исправления 2026-06-04 (fix8 + fix9):**

| Проблема | Решение |
|----------|---------|
| Старый `zoneIndex` не совпадал с новой шириной | `_assignFurnitureZonesAndGaps(..., { forceByPosition: true })` при смене `innerWidthMm` или флаге `_relayoutZonesFromPosition` |
| `mixedLeftSingle`: шкаф попадал не в последнюю зону | При `forceByPosition` — сначала тумбы слева направо, затем `FLOOR_IN_NICHE` в зону `parts−1` |
| Мебель визуально не в синих линиях после resize | `_assignZonesByModuleSegments` по центру bbox; `_snapFurnitureBBoxToZoneEdges`; `moduleWidth = endU−startU`; fallback границ из `_layoutCache.segments` |
| Clodis не меняет ширину при resize (только сдвиг) | При `__cldSkipSectionAutoRescale` — **`rebuildFurnitureGroupForSectionResize`** из `__clodisDataForBuild` + новый `sectionSize` (как при размещении), не uniform-scale |
| `customZoneWidthsMm` не влезали в новую ширину | Пропорциональное ужатие custom-зон под `sectionWidth − caps` |
| Повторный `updateFurnitureInSection` накапливал scale | Bbox при `scale=1`, итог `grp.scale.set(sx,sy,sz)` абсолютно |

**Функции:** `updateSectionSize`, `computeSectionLayout`, `updateFurnitureInSection`, `_assignFurnitureZonesAndGaps`, `_assignZonesByModuleSegments`, `_snapFurnitureBBoxToZoneEdges`.

**Проверка (§9-K):** шкаф + 3–4 тумбы → уменьшить/увеличить ширину секции или отступ слева → мебель в ряд без пересечений, `[ZONE-WIDTH]` при ужатии custom.

### 13.8. Пара однодверная ↔ двустворчатая (любой элемент каталога)

**Админка → «Основные»:**

1. **Метка в комнате** — `Однодверный` / `Двустворчатый` (поле `data.doorKind`; теги категорий подставляются автоматически).
2. Копию элемента — в списке каталога; у копии — противоположная метка и дверь в конструкторе.
3. **Связать с…** — связь `pairedCatalogItemIds` с парной карточкой.

**Комната:** элемент с меткой виден только на пилюле того же типа; в чужую зону не ставится (переключение пилюли). При resize зоны — подмена связанной карточки (`tryApplyDoorPairCatalogSwap`, `[door-pair]`).

**Быстрый сценарий (комод и т.д.):** создать → метка «Однодверный» → сохранить → копия в списке → метка «Двустворчатый» + вторая дверь → «Связать с…» → выгрузить в конструктор → Ctrl+F5.
