# Референс: «Добавить 3D модель» (cabinet_model)

## Для чего это нужно

**Каталог 3D моделей** (`cabinet_model`) в PlanPlace — это справочник **готовых 3D-моделей** (FBX и т.п.), которые можно подставлять в конструктор **вместо сборки модуля из стен**.

- В **каталоге элементов** (Кухни, Двери и т.д.) модуль собирается из **секций и стен** (дерево конструктора).
- **3D модель** — это один элемент каталога с типом `model`: в сцене показывается **один загруженный меш** (файл .fbx и т.д.), а не разложенная геометрия.

То есть: «Добавить 3D модель» = добавить запись в каталог таких «готовых мешей», чтобы потом их можно было ставить в комнату как отдельные объекты (техника, декор, корпус из одной модели и т.д.).

---

## Как это устроено в референсе

### 1. Список (Список 3D Моделей)

- URL: `catalog/items/cabinet_model` (или через меню «Каталог 3D моделей» → «Список 3D Моделей»).
- Загрузка: `GET /catalog/items_get/cabinet_model`, категории: `GET /catalog/categories_get/cabinet_model`.
- В таблице для `cabinet_model` показывают, в том числе, **модели** из `item.data.params.models` (код и т.д.), а не варианты размеров как у обычных модулей.

### 2. Добавление / редактирование одной записи

- Открывается форма редактирования **элемента каталога** с `controller_name = cabinet_model`.
- Данные одной записи хранятся в `item.data` (JSON). При загрузке формы делают `params = JSON.parse(item.data).params`.
- Для отображения в конструкторе используется та же страница/логика, что и для других типов каталога (общие поля: название, категория, иконка, порядок, отображение в спецификации/конструкторе и т.д.).

### 3. Структура данных одной 3D модели (params)

В референсе у элемента каталога типа `cabinet_model` в `item.data` лежит объект с полем **`params`**. Внутри него важно:

- **`params.models`** — массив вариантов модели. Каждый элемент описывает один вариант 3D-модели с привязкой к размерам и пути к файлу:
  - **`model`** — путь к файлу модели (например `/common_assets/models/... .fbx`). Если пусто — подставляется `no_model.fbx`.
  - **`code`**, **`name`**, **`price`** — артикул, название, цена.
  - **`min_x`, `min_y`, `min_z`** и **`max_x`, `max_y`, `max_z`** — диапазоны размеров (в мм), в которых этот вариант подходит. В конструкторе по текущему размеру секции выбирается подходящий вариант (или fallback на `no_model.fbx`).
- Могут быть **`params.variants`**, **`params.show_in_spec`** и другие общие для каталога поля.
- Размер по умолчанию корневой секции задаётся, например, в **`params.size`** или в корне (как в `def_cabinet_model`: `size: { x: 100, y: 100, z: 100 }`).

То есть одна запись «3D модель» в каталоге может содержать **несколько вариантов** (разные файлы под разные диапазоны размеров), описанных в `params.models`.

### 4. Как с этим работает конструктор (движок)

- В сцене используется класс **`CabinetModel`** (наследник `CabinetSection`).
- При построении секции вызывается **`_get_model()`**: по текущему размеру секции (width, height, depth) перебирается `params.models` и выбирается запись, у которой размер попадает в диапазоны `min_x..max_x`, `min_y..max_y`, `min_z..max_z`.
- Затем вызывается **`_load_model(model_path, materials, params)`** — загрузка меша (FBX и т.д.) и применение материалов.
- В спецификации учитываются `code`, `name`, `price` выбранного варианта и настройки показа в спецификации.

Итого: «Добавить 3D модель» в рефе — это создание/редактирование **элемента каталога** с типом `cabinet_model`, у которого в `data.params` заданы варианты моделей (`params.models`) с путями к файлам и диапазонами размеров.

---

## Как с ней работать (по референсу)

1. **Добавить запись** — открыть «Список 3D Моделей» → «Добавить» (или аналог). Откроется форма редактирования элемента каталога `cabinet_model`.
2. **Заполнить основные поля**: название, категория, отображение в спецификации/конструкторе, порядок, иконка.
3. **Заполнить параметры 3D модели** (то, что у нас во вкладке «Параметры» / «Модель»):
   - хотя бы один вариант в **`params.models`**:
     - **model** — путь к файлу (например `/common_assets/models/... .fbx`);
     - **code**, **name**, **price**;
     - **min_x, min_y, min_z**, **max_x, max_y, max_z** — под какие размеры (мм) этот вариант показывать.
4. **Превью** в форме редактирования — чтобы визуально проверить размеры и, при необходимости, вид секции/объёма (в рефе это может быть тот же превью-движок, что и для каталога элементов).
5. **Сохранить** — отправка на сервер (например `item_add` / `item_update` для `cabinet_model`) с сохранением `item.data` (в т.ч. `params.models`).

После сохранения эта запись попадает в каталог и может подставляться в сцену как тип `model` (одна 3D-модель по выбранному размеру).

## Форматы готовых моделей (загрузка)

**Да, загружать можно готовую модель.** В референсе и в нашем проекте поддерживаются такие форматы:

| Формат   | Расширение | Референс PlanPlace      | Наш проект (Three.js) |
|----------|------------|--------------------------|------------------------|
| **FBX**  | `.fbx`     | ✅ основной (load_exact_model) | ✅ при наличии FBXLoader |
| **GLTF** | `.gltf`    | ✅ есть GLTFLoader       | ✅ GLTFLoader          |
| **GLB**  | `.glb`     | ✅ (бинарный GLTF)       | ✅ GLTFLoader          |
| **OBJ**  | `.obj`     | ✅ есть OBJLoader        | ✅ OBJLoader           |
| **STL**  | `.stl`     | —                        | ✅ (в форме загрузки) |
| **3DS**  | `.3ds`     | ✅ TDSLoader             | —                      |
| **Collada** | `.dae`   | ✅ ColladaLoader         | —                      |

- В **референсе** для каталога 3D моделей в коде в основном используется **FBX** (пути вида `/common_assets/models/... .fbx`), при этом в движке подключены и GLTFLoader, и OBJLoader.
- В **нашем проекте** в форме загрузки явно указаны форматы: **`.glb`, `.gltf`, `.obj`, `.stl`**.

**Рекомендация:** для новых готовых моделей лучше использовать **GLB/GLTF** (современный формат, одна геометрия + материалы) или **FBX** (как в референсе). **OBJ** подходит для простых мешей без сложных материалов.

## Итог

- **Для чего**: справочник готовых 3D-моделей (файлы .fbx и т.д.) для подстановки в конструктор вместо «собранного» модуля.
- **Как работает в рефе**: форма «Добавить/редактировать элемент каталога» с `controller_name = cabinet_model`; ключевые данные — в `item.data.params` (в т.ч. массив `params.models` с путями к файлам и диапазонами размеров).
- **Как работать**: добавить запись → заполнить название, категорию, варианты моделей (путь, размеры, артикул/цена) → сохранить; в конструкторе по размеру секции выбирается подходящий вариант и загружается его 3D-файл.
