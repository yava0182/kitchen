# Комната и каталоги: как модели попадают в сцену

## Две сцены в проекте

| Сцена | Где | Назначение |
|-------|-----|------------|
| **Превью модуля** | Админка → вкладка «Конструктор» → iframe `constructor-clodis.html` | Одна сцена Three.js: один модуль (секция + детали/фасады). Нужна только для редактирования элемента каталога. |
| **Комната** | Клиентский конфигуратор `index.html` (Room Configurator) | Одна сцена Three.js: `Room` (пол, стены, потолок) + несколько `Furniture` (модули из каталога). Пользователь расставляет мебель по стенам. |

Итого: **движок сборки одного модуля** один (формат section/wall/facade/module). Используется в двух местах:
- в админке — **constructor-clodis.js** (iframe);
- в комнате — **ClodisBuilder.js** (сборка из JSON для каждого экземпляра Furniture).

---

## Как модели попадают в комнату (текущая схема)

1. **Каталог в конфигураторе комнаты**  
   Сейчас источник каталога — **localStorage**: ключи вида `catalog_<тип>` (например `catalog_1` для Кухонь). В `main.js` вызывается `loadSavedModels()`: читаются все ключи `catalog_*`, для каждого элемента ожидается поле **`clodisJSON`** (массив section/wall/facade, как в админке).

2. **Отображение в сайдбаре**  
   Элементы каталога рисуются в `#cabinets-grid`. У каждого элемента при клике вызывается `startFurniturePlacement(furnitureData)`, где `furnitureData` — это `item.clodisJSON` (или `item.data`).

3. **Размещение на стене**  
   Пользователь кликает по стене → `placePendingFurniture()` → создаётся экземпляр `new Furniture(clodisData, params)` → внутри `Furniture.buildFromClodis()` вызывается **ClodisBuilder.buildFromJSON(jsonData)** → строится Three.js группа (секция + детали) → эта группа добавляется в общую сцену комнаты: `scene.add(furniture.group)`.

4. **Формат данных**  
   И админка (constructor-clodis), и комната (ClodisBuilder) ожидают один и тот же формат: массив верхнего уровня с элементами `{ type: 'section'|'wall'|'facade'|'module', ... }`. В админке это `template.structure` / `clodisJSON`; при сохранении уходит `constructor_structure` с полем `template.structure`. Для комнаты нужен именно массив «движкового» дерева (clodisJSON / template.structure).

---

## Каталоги: что есть и чего не хватает

- **В админке** каталоги уже есть: типы (Кухни, Двери, …), элементы каталога с `constructor_structure` хранятся в API (сохранение через «Сохранить»).
- **В конфигураторе комнаты** каталог сейчас берётся только из **localStorage** (`catalog_*`). Загрузки каталога с бэкенда по API в index.html нет.

Чтобы модели из админки гарантированно попадали в комнату, нужно одно из двух:

**Вариант A — синхронизация через localStorage (уже частично есть)**  
- В админке при действии вроде «Выгрузить настройки в конструктор» или при сохранении элемента дополнительно писать в localStorage ключ `catalog_<тип>`: массив элементов с полем `clodisJSON` (или `data`), полученным из `constructor_structure.template.structure` (или из текущего дерева).  
- Тогда в комнате `loadSavedModels()` уже подхватит эти данные; условие — пользователь сначала зашёл в админку и «выгрузил» каталог.

**Вариант B — загрузка каталога из API в конфигураторе комнаты**  
- В `index.html` / `main.js` при старте (или при выборе типа комнаты/каталога) вызывать API, например:  
  `GET /api/catalog/items_get/<catalogType>` (или аналог, который возвращает список элементов с `constructor_structure`).  
- Для каждого элемента из ответа формировать `clodisJSON` из `constructor_structure.template.structure` (или из корневого массива, если API отдаёт его напрямую).  
- Заполнять `#cabinets-grid` этими элементами и при клике передавать в `startFurniturePlacement` соответствующий `clodisJSON`.  
- Тогда комната не зависит от localStorage и всегда показывает актуальный каталог с сервера.

---

## Рекомендуемый следующий шаг

1. **Определиться с источником каталога в комнате**  
   - Либо доработать «Выгрузить настройки в конструктор», чтобы в localStorage попадали все нужные типы каталога с `clodisJSON`.  
   - Либо ввести загрузку каталога по API в конфигураторе (Вариант B) и по возможности оставить localStorage только как кэш или запасной вариант.

2. **Единый формат при передаче из API в комнату**  
   - Убедиться, что при отдаче элемента каталога (из API или из localStorage) в конфигуратор передаётся массив «движкового» дерева (то, что сейчас в админке в `template.structure` / clodisJSON).  
   - В комнате при создании `Furniture(clodisData)` передавать именно этот массив (или первый элемент, если по контракту ожидается одна корневая секция); ClodisBuilder уже умеет и массив, и один объект.

3. **Проверка совпадения формата**  
   - Сохранить в админке элемент с деревом (секция + детали/фасады) → открыть конфигуратор комнаты → убедиться, что этот же элемент появляется в каталоге и при размещении строится через ClodisBuilder без ошибок. При расхождениях — приводить формат в API/localStorage к тому, что ожидает ClodisBuilder (section/wall/facade/module).

После этого цепочка «каталог в админке → комната» будет явной: один формат JSON, один движок сборки (ClodisBuilder в комнате), две сцены — превью модуля и комната.
