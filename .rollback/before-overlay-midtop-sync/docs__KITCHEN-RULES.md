# Правила кухни CLODIS (живой контракт)

Документ дополняем по мере решений. Код подстраиваем под него, а не наоборот.  
Связанный обзор: [`KITCHEN-DOMAIN.md`](./KITCHEN-DOMAIN.md).

**Статус (2026-10-10):** зафиксированы глубина ряда, ритм высоты, НМ / пенал / НШ1 / НШ2.  
**Проверка:** НШ2 в комнате (Ctrl+F5, `nsh2-2`).

---

## 0. Железные запреты

1. **Ни один модуль не входит в меш стены** (толщина комнаты ~100 мм снаружи ряда).
2. **Не якорить посадку к bbox меша стены** — только к плоскости ряда.
3. **Пенал ≠ НМ** в UI и rebuild: нельзя гнать пенал через стек столешки (10+корпус+40).
4. **Пенал ≠ высота ниши до потолка** — только формула датамов.
5. **Не заявлять «готово» без проверки на «Сбоку»:** пенал + НМ рядом; НШ1 на mid/high; НШ2 низ = верх НШ1/пенала.
6. **Rebuild вкладки каталога не должен двигать/раздувать модули** (Y/H/zoneIndex).
7. **НШ2 ≠ `wall_hung_high` по Y** — никогда не сажать 2-й ярус от потолка.

## 2. Глубина — НМ (рабочий стол)

Стек (мм), столешка проекта `Dwt` (дефолт **600**):

```
W ──[+ rear 10]── корпус (Dwt−40−10) ──[+ front 40]── торец столешки (W+Dwt)
```

При `Dwt = 600`: зад корпуса **+10**, перед **+560**, торец столешки **+600**.

- Столешка и цоколь ряда — **только на НМ**.
- Якорь столешки по глубине — **только пивот секции**.

### 2.1 Лицевой цоколь-прогон (BASE)

| Правило | Смысл |
|---------|--------|
| Span U | Корпус (`moduleWallSpanU`); непрерывность «цоколь = ячейка с pad» — **цель**, не в коде без отдельной сессии |
| Inset | Как в админке: **16 мм** вглубь от переда корпуса |
| Цвет | Дефолт белый ЛДСП; отдельный выбор «цоколь» — позже |
| Пенал | Пока барьер прогона; сквозной / свой кусок — отдельное решение |
| Раскрой | Позже по готовым прогонам (≤3 м и т.п.), не в посадке мм |

Код: `kitchen-run-overlays.js` (`KitchenPlinthRun`).  
Нельзя чинить continuity через `kitchen-side-panels*` / footprint L — это ломает канон накладок.

## 4. Высота — ритм колонки (зафиксировано)

**Источник правды (Управление комнатой 2 → «Вертикальный ритм кухни»):**

| Что | Откуда читается | Дефолт |
|-----|-----------------|--------|
| Обычная НМ (`bandLow`) | `placementKindProfiles.kitchen_base.settings.carcassHeightMm` | **720** + опоры |
| Gola НМ (`bandLow`) | `placementKindProfiles.kitchen_base_gola.settings.carcassHeightMm` | **780** + опоры |
| НМ → НШ1 (`bandMid`) | `kitchenRhythm.bandMidMm` (default + вилка min/max); в проекте можно сузить | **600** (560–650) |
| Остальное | опоры проекта, H НШ1/НШ2, толщина столешки внутри mid | переменные |

При смене mid в допуске — пересчёт низа НШ1 и высоты пенала. Пусто в проекте = default из админки.

Якорь mid — **верх корпуса НМ**, не верх столешки. Столешка лежит внутри mid.

```
пол
 └── цоколь (100/120/150)          ← переменная
      └──[low 720 | Gola 780]──┬── mid 600 LOCKED ──┬──[high: НШ1]──┬──[top: НШ2]
         корпус НМ             │ столешка внутри    │  переменная   │ antresol
                               └────────────────────┘               └─ отдельно от корпуса пенала
```

Gola НМ: корпус **780** + опоры (100/120/150), без снижения.  
На боковинах — **выемки** (отсечение торца, не паз в пласть), инструмент конструктора «Выемка», фреза **Ø6** (R=3) → CFRN sign `Выемка Ø6`:  
- **L** верх: высота ≈57.5, глубина с торца **27**, в материал = толщина  
- **C** (Boyard RP050): высота **73.5**, с торца **27**, центр на **360** мм от низа корпуса  
- **2 ящика:** каждый фасад **343** мм (343 + зазор C + 343 + зона L = 780)  
В админке: боковина → Добавить → **Выемка** (Ø фрезы / R / глубина с торца).


| Параметр | Роль | Дефолт |
|----------|------|--------|
| `plinthHeightMm` | цоколь | 100 / 120 / 150 |
| `bandLowMm` | корпус НМ | **720** (Gola: **780**) |
| `bandMidMm` | верх НМ → низ НШ1 | **600** (locked, `INFO_BAND_MID_MM`) |
| `bandHighMm` | корпус НШ1 | **в потолок:** pick 860/920/960; иначе legacy 720 |
| `bandTopMm` | корпус НШ2 (антресоль) | **в потолок:** H1/2; иначе legacy 360 |
| `worktopThicknessMm` | внутри mid | 38 / 12 / … |
| `clearanceAboveWorktopMm` | mid − thickness | производное |

**Корпус пенала** = low + mid + high (при в потолок high = pick; иначе 720 → 2040).  
Цоколь под пеналом отдельно. Верх корпуса пенала = низ НШ2.

Смена столешки 38↔12 **не** двигает пенал и **не** двигает низ НШ1.

**Смена опор 100↔120↔150:** двигается **вся колонка** как границы от пола:
`пол → plinth → low → mid → high → top`.  
Корпуса H (720/600/720/360) не меняются; сдвигаются только Y низов.  
НШ1/НШ2 **не** хранят залипший clearance — всегда `plinth + сумма поясов`.

## 4a–4b. НШ1 / НШ2 — тест «кухня в потолок»

Эталон (пока): **до потолка, не выше**. НМ + mid без изменений. Гориз. сетку/модули не трогаем.

| Ярус | Стандарт H (мм) |
|------|-----------------|
| НШ1 | **860 / 920 / 960** |
| НШ2 | **ровно половина** → 430 / 460 / 480 |

Подбор: из 6 размеров берём **наибольшую** пару `H1 + H1/2`, чтобы  
`plinth + bandLow + 600 + H1 + H2 ≤ высота комнаты` (`bandLow` = 720 / Gola 780). Ниже — можно; выше — нельзя.  
Если ни одна пара не влазит (типично room ≤2700 при цоколе 100) — legacy 720/360.  
Мин. room под 860+430 (non_gola): **plinth + 2610** (при 100 → **2710**).

| | НШ1 | НШ2 |
|--|-----|-----|
| Низ от пола | plinth+bandLow+600 | plinth+bandLow+600+H1 |
| H | выбранный H1 | H1/2 |
| API | `resolveKitchenWallTiersToCeilingMm` | то же |

Пенал high-дата = H1 (верх корпуса = низ НШ2).

## 4c. Cohabit в одной ячейке

Группа `kitchen_column`, роли (разные → можно вместе):

| Роль | Модуль |
|------|--------|
| `base` | НМ |
| `mid` | НШ1 |
| `top` | НШ2 |
| `full` | пенал (сносит base/mid; **с top — да**, антресоль сверху) |

В ячейке допустимо: НМ+НШ1, НМ+НШ1+НШ2, пенал+НШ2, только НШ1+НШ2, и т.д.  
Нельзя: два `mid`, два `base`, пенал+НМ, пенал+НШ1.

Шкафной `wall_column` по-прежнему только `base`+`upper`.

## 4d. Секция из стандартных ячеек → модуль из каталога

Простая схема:

1. **Секция** режется на **стандартные ячейки** (сетка ширин).
2. В ячейку тащим модуль из каталога: **однодверный** или **двухдверный** — смотря какая ячейка.
3. Всё, что пользователь меняет и **не совпадает** с стандартными размерами → **нестандарт** (тянем).

| | Что |
|--|-----|
| Стандарт | ячейка сетки + подходящий SKU из каталога, как есть |
| Нестандарт | ширина/размер уехали от сетки/SKU |

Посадка только в ячейку (`zoneIndex`). Вертикаль — датамы (опоры + пояса).

## 6. Угловой НМ (контракт, 2026-10-12)

Карточка: catalog_44 «Стол угловой». `placementKind` → **`kitchen_base_corner`**.

### 6.1 Спец-ячейка углового = **1050** (не 1040)

```
|◀──────── спец-ячейка / столешка s:x = 1050 до стены ────────▶|
|← корпус 1040 (−10 мм от боковой стены) →|←10→|
|← return 550 →|← нога/фасад 500 →|  (после приставки)
```

- **Ячейка / столешка = 1050** до боковой стены (не ужимать ячейку).
- **Корпус НМУ = 1040** (`s:x − v:side_wall_clearance_mm`, зазор 10 мм к стене).
- Столешка тянется на всю спец-ячейку 1050 до стены.
- Цоколь НМУ: вдоль открытой ноги **до приставки** и там **поворот** (return-панель); стык со боковым НМ на другой стене — когда его поставят. Не тянуть прямой цоколь под весь return.
- Остальные однодверные на свободном плече L — свой S (как на прямой), не 1050.
- W+10 сзади — посадка корпуса по глубине (§2).

| Часть | Роль | Формулы (правый угол) |
|-------|------|------------------------|
| Корень | `cabinet_root` | `s:x × s:y × s:z` |
| Цоколь | `plinth` | доски модуля; L-поворот — отдельно |
| Приставка | `corner_return_mm` | **= D** = глубина корпуса соседа / project carcass (не залипать 550) |
| Корпус НМ | `corpus` | `size.x = s:x − 10 − return`; `pos.x = v:corner_side_inset_mm`; `size.z = s:z` |
| Секция-слот | **`corner_return`** | полупрозрачная (tint orange): `x=return`, `z=40`, `pos.x=v:corner_return_pos_x`, `pos.z=s:z−40` |
| Внутри слота | live «Приставной углового» | заполняет слот; внутрянка (g0 + уголок) — отдельно |

**Суть:** к НМУ добавлена цветная полупрозрачная секция-карман 40 мм спереди × D по U; в ней — приставка.

**Запрещено:** растягивать слот `size.z = s:z`.

### 6.2 Ширина слепой зоны vs толщина слота

| Что | Размер |
|-----|--------|
| Слепая зона вдоль стены (U) | `corner_return_mm` = **D** (550 @ Dwt600 / 460 / …) |
| Толщина секции-слота (Z) | **40 мм** |
| `corner_return_pos_x` | у стены: `s:x − 10 − return` (или `10` если угол atStart) |
| Комната | `corner_return_mm` = `resolveKitchenCornerReturnMm()` (= project carcass); ячейка = 500+D |

### 6.3 Статус дерева (catalog_44)

| Узел | Формула |
|------|---------|
| corpus / plinth | `s:x − 10 − return` |
| Приставка (секция) | `return × (s:y−цоколь) × 40`, спереди |
| внутри | live catalog_45 id=6 «Приставной углового» |
| pk | `kitchen_base_corner` |
| var | return=D; depth=40; `corner_return_pos_x` |

Роли: `corner_return`, `corner_post` (legacy).
